扩散模型怎么做强化学习：从 Cosmos3 的双塔讲到一轮 FlowGRPO

我最近在给开源项目 UniRL 加 NVIDIA Cosmos3-Nano 的文生图和 RL 训练配方。代码能跑通之后，我发现自己有两件事讲不清楚：这个「双塔」模型到底是怎么把文字和图像接在一起的，以及一个扩散模型凭什么能做强化学习。这篇文章是我把这两件事问明白的过程。

我带走的一句话是：给扩散模型做 RL，就是在几步去噪里加一点噪声，把「下一个 latent」变成一个能算概率的动作；模型是双塔还是单塔，只决定这一步前向里文字怎么被读到。

全文分六部分：先分清扩散和 transformer 的关系，再看 Cosmos3 的双塔和 MiniMax-H3 的单塔，然后讲加噪声怎么带来 log-prob，接着走完一轮 FlowGRPO，最后看一条不需要 log-prob 的路 DiffusionNFT。文中标着「我卡住的地方」的小块，是我当时真的问出口的问题。

文中的结构和数字来自 UniRL 仓库的代码、配方文件和 diffusers 里的 transformer_cosmos3.py。

扩散和 transformer 不是二选一

我卡住的地方：H3 能同时出视频和音频，它是扩散还是 transformer？我知道图片有 diffusion 和 transformer。

两个都是。它们回答的是不同的问题。扩散（包括 flow matching）说的是怎么生成：从噪声出发，一步步去噪。transformer 说的是用什么网络：每一步去噪时，负责算「该往哪走」的那个神经网络。

这两个维度可以自由组合。Stable Diffusion 1.5 是扩散方法配卷积 U-Net。SD3、Flux、Cosmos3 的生成塔、H3 都是扩散方法配 transformer。把图片切成离散 token 再逐个预测的那类模型，是自回归方法配 transformer。我之前以为的「diffusion 和 transformer 两派」，其实是同一种网络配了两种生成方法。

本文两个模型用的都是 flow matching。约定是

\[ x_t = (1-\sigma)\,x_0 + \sigma\,\varepsilon \]

其中 \(x_0\) 是干净的 latent，\(\varepsilon\) 是高斯噪声，\(\sigma\) 从 1 降到 0。模型预测速度 \(v = \varepsilon - x_0\)。采样就是让 \(\sigma\) 分若干步降到 0，每步走一小段 \(x \leftarrow x + v\,dt\)，其中 \(dt = \sigma_{\text{next}} - \sigma < 0\)。这叫 Euler 步。

文字怎么进模型：Cosmos3 的双塔

Cosmos3-Nano 约 16B 参数，是一个 Mixture-of-Transformers（MoT）：约 8B 的理解塔读文字，约 7B 的生成塔预测速度。它没有单独的文本编码器。

理解这个设计，先要和另外两种结构放在一起看。

本文的两个模型分别是 (b) 和 (c)。(a) 是常见的文生图结构，放在这里当参照：H3 的文字路径和它一样，区别在于主干同时处理视频和音频两种 token。

塔的判断标准是：同一层里，不同模态是不是用不同的一套主干权重。 Cosmos3 的每一层 Cosmos3VLTextMoTDecoderLayer 里，文字走 to_q / to_k / to_v / to_out 和 mlp，图像走 add_q_proj / add_k_proj / add_v_proj / to_add_out 和 mlp_moe_gen。所以是两座塔。

一次前向里形状怎么变

以 832×480 的单张图为例。VAE 是 Wan2.2 的，48 个通道，空间上压缩 16 倍，所以 latent 是 [48, 1, 30, 52]。

图里理解塔那一格写的 causal，在训练和推理时是同一条规则。prompt 是完整给定的，所以一次前向就把所有文字位置并行算完，但每个文字 token 仍然只看得到它前面的文字。

几个数字的来历：

  • 390 个图像 token：30×52 的网格每 2×2 合成一块，得到 15×26 = 390 块。每块把 4 个位置的 48 个通道拼起来，是 192 维，再由 proj_in 变成 4096 维。
  • 时间步只在入口加一次：\(\sigma \times 1000\) 经过 time_embedder 变成向量，加到带噪的图像 token 上。文字 token 不加。
  • 出口和入口对称：proj_out 把 4096 维变回 192 维，拼回 [48, 1, 30, 52]，就是速度 \(v\)。

层数 36、隐藏维度 4096、查询头 32、键值头 8、词表 151936 是 diffusers 里这个类的默认参数。我用它们估算的参数量和 Nano 的规模对得上，但没有直接读检查点的 config 确认。

一层里注意力算两遍

「生成塔能看理解塔，反过来不行」不是靠一张大的注意力掩码实现的，而是直接分两次算：

  • 第一遍：文字的 Q、K、V 都来自文字，因果注意力，每个文字 token 只看它前面的文字。
  • 第二遍：Q 来自图像（add_q_proj），K 和 V 是「文字的」和「图像的」拼在一起。图像 token 能看到全部文字和全部图像。

第二遍里借来的文字 K、V，是理解塔自己的 to_k / to_v 算出来的。生成塔没有另外一套权重去处理文字。

我卡住的地方：生成的时候，文字 token 是一次给全的吗？训练的时候呢？

是，两种情况都是。分词在生成开始前做一次，得到正、负 prompt 两串固定的 token。之后每一步前向都把整串文字和当前的图像 latent 拼成一条序列。理解塔在这里只当阅读器用，不会逐词往外生成。因果掩码是结构，自回归采样是用法，这里只有前者。训练时也一样：SFT 的损失只算在带噪的图像 token 上，RL 回放用的就是采样时存下的那两串 token。diffusers 的 forward 里 lm_head 存在，但没有被调用。

我卡住的地方：那为啥要每层都连？算一次，之后每次前向拼进去不就完了。

关键在「拼一次」拼的是什么。图 (a) 的结构也把文字拼进序列，但拼的是编码器最后一层的输出，之后由扩散模型用自己的权重重新加工。双塔让生成塔第 \(\ell\) 层直接读理解塔第 \(\ell\) 层的表示，浅层的字面信息和深层的语义信息都用得上；生成塔的参数只管图像；理解塔的权重不被改动，仍然是一个完整的语言模型。

我的直觉对了一半：文字看不到图像，又不带时间步，所以理解塔每一层的结果在 16 步去噪里完全相同，理论上可以算一次存起来，只是要存每一层的 K、V 而不是一层输出。但按现在的代码，每次前向理解塔都从第 1 层重算到第 36 层。

小结：双塔对训练的含义很直接。理解塔冻结。LoRA 只挂在生成塔的注意力上，也就是 add_q_proj / add_k_proj / add_v_proj / to_add_out。

单塔的 H3，和其他多模态路线

MiniMax-H3 是另一种结构：输入文字，输出视频加立体声音频，33B 参数。它的文字由一个单独的 Qwen3-VL 编码成向量，然后和视频、音频的 token 一起进入同一个扩散 transformer。

做法分四步。视频和音频各有一个 VAE，先压成一串向量。三种 token 拼成一条序列，每个 token 带着「我是哪种模态」和「我在时间、空间上的位置」。一个 transformer 对整条序列做自注意力，输出视频速度和音频速度。两边各走一步，重复 10 步。

声音和画面能对上，靠的是第三步里视频 token 和音频 token 互相能看到。两边是一起从模糊变清晰的，所以关门的画面和关门的声音会落在同一时刻。

我卡住的地方：我能把 H3 理解成三塔吗？

不能，它是一座塔开了三个门。H3 的每个 block 里只有一份注意力和一份前馈层，三种 token 过的是同一套权重。按模态区分的只有三处，都很薄：入口各有一个线性层，出口各有一个线性层，每层归一化之后的缩放和偏移按「时间步 × 模态」查表。

把两个模型并排放在一起：

Cosmos3-Nano MiniMax-H3
参数量 约 16B（理解塔约 8B，生成塔约 7B） 33B，另有单独的文本编码器
结构 双塔，每层两套权重 单塔，每层一套权重
文字怎么进来 token 直接进理解塔，每层的 K、V 被生成塔读取 Qwen3-VL 编码成向量，拼进序列
每次前向输出 图像 latent 的速度 视频 latent 和音频 latent 各一份速度
最终产物 图像（本文只用单帧） 视频加立体声音频
时间步怎么注入 入口加一次 每层归一化后按「时间步 × 模态」调制
能不能出文字 理解塔带 lm_head，文生图路径里没用到 不能
LoRA 挂在哪 只挂生成塔的注意力 共用的注意力和前馈层

最后一行是结构差异直接带来的。Cosmos3 可以只挑生成塔的层来训。H3 没有这种划分，LoRA 一旦挂上，文字、视频、音频三种 token 的处理都会被改动。

我卡住的地方：多模态都是这么训的吗，让它既能输出文字又能输出图片？

不是，双塔只是其中一条路线。别的路线还有：语言模型写出 prompt 交给独立的文生图模型；把图像也切成离散 token，和文字放进同一个词表统一预测下一个 token（Chameleon）；同一个 transformer 上文字位置做下一词预测、图像位置做扩散（Transfusion）。它们回答的是同一个问题：文字是离散的，图像是连续的，怎么放进一个模型。

另外，Cosmos3 的两种能力不是一起训出来的。文字能力来自理解塔，训练时冻结；图像能力来自生成塔。H3 则根本没有文字输出。

我卡住的地方：音视频的训练压力完全取决于帧数吧？

更准确地说取决于 token 总数，帧数是其中一个乘数。但在 H3 这里帧数不是能随便调的旋钮：VAE 在时间上也压缩，124 帧像素对应 37 个 latent 帧；帧率固定 24 fps，124 帧是最小的合法值。配方里实际用来省显存的是分辨率，256×384 时回放每步约 2.2 GB，768×768 时约 12 GB。

确定性采样为什么做不了策略梯度

策略梯度需要知道「这个动作的概率有多大」，也就是 log-prob。Euler 步里，给定当前 latent，下一个 latent 是唯一确定的，没有概率可言。

确定性采样并不是每次出同一张图：起始噪声是随机抽的，换一份噪声就是另一张图。但起始噪声的分布和模型参数无关，提供不了梯度。另外，这里说的做不了只限于需要 log-prob 的策略梯度，后面的 DiffusionNFT 用的就是确定性采样。

解决办法是在某几步往结果里加一点高斯噪声。

这样「下一个 latent」就服从一个高斯分布，模型的输出决定这个高斯的均值。对应到 RL 的词汇：

RL 这里
状态 当前 latent \(x\)、步号、prompt
动作 下一个 latent \(x_{\text{next}}\)
策略 高斯 \(\mathcal{N}(\mu, \text{std}^2)\)，\(\mu\) 由带 LoRA 的模型决定
轨迹 16 步去噪的整条链
奖励 只在最后给：解码成图，打一个分

FlowSDE 的均值和方差

Cosmos3 的配方用 FlowSDEStrategy。记 \(s = \eta\sqrt{\sigma/(1-\sigma)}\)，代码里的均值化简后是

\[ \mu = x\left(1 + \frac{\eta^2\,dt}{2(1-\sigma)}\right) + v\left(1 + \frac{\eta^2}{2}\right)dt \]

\[ \text{std} = s\,\sqrt{-dt}, \qquad x_{\text{next}} = \mu + \text{std}\cdot z,\quad z \sim \mathcal{N}(0, I) \]

\(\eta\) 控制噪声的大小。\(\eta = 0\) 时均值退回 \(x + v\,dt\)，标准差为 0，就是 Euler 步。所以同一个类两种步都能走，代码里靠 eta if index in sde_set else 0.0 切换。

代入数字走一遍。第 8 步 \(\sigma = 0.75\)，下一步 \(\sigma_{\text{next}} = 0.70\)，\(dt = -0.05\)，\(\eta = 0.7\)。那么 \(s = 0.7\sqrt{3} \approx 1.21\)，\(\text{std} \approx 1.21 \times \sqrt{0.05} \approx 0.27\)，均值是 \(0.951\,x - 0.062\,v\)。

log-prob 是高斯的对数密度，每个元素

\[ \log p = -\frac{(x_{\text{next}} - \mu)^2}{2\,\text{std}^2} - \log \text{std} - \tfrac{1}{2}\log 2\pi \]

有两个细节容易漏。第一，代码对所有 latent 维度取的是平均而不是求和，所以数值很小，clip_range 才会取到 1e-3 这个量级。第二，式子里的 \(x_{\text{next}}\) 被 .detach() 了，梯度只经过 \(\mu\)，也就是只经过模型输出 \(v\)。

CPS：另一种加噪声的方式

H3 的配方换成了 CPSSDEStrategy，注释里的理由是 FlowSDE 在 \(\eta = 0.7\) 时会让画面出现噪点。

FlowSDE 是在原有步子上额外加噪声。CPS（coefficients-preserving sampling）先从当前状态估出干净图和噪声两个成分：

\[ \hat{x}_0 = x - \sigma v, \qquad \hat{\varepsilon} = x + (1-\sigma)\,v \]

然后把估出的噪声成分缩小，再补上新的噪声：

\[ \mu = (1-\sigma_{\text{next}})\,\hat{x}_0 + \sigma_{\text{next}}\cos\!\left(\tfrac{\eta\pi}{2}\right)\hat{\varepsilon}, \qquad \text{std} = \sigma_{\text{next}}\sin\!\left(\tfrac{\eta\pi}{2}\right) \]

因为 \(\cos^2 + \sin^2 = 1\)，旧噪声和新噪声合起来的系数正好是 \(\sigma_{\text{next}}\)，和日程规定的噪声水平一致。它的 log-prob 在代码里也更简单，直接是 \(-(x_{\text{next}} - \mu)^2\)，不除以方差。

CFG 怎么参与

我卡住的地方：Cosmos3 有 cond 和 uncond 两次前向，一般都有 CFG 吗？

大多数有，但不是全部。CFG（classifier-free guidance）的做法是训练时随机把一部分 prompt 换掉，让同一个模型既会「按 prompt 画」也会「随便画」；采样时两种都算，再外推：\(v = v_{\text{uncond}} + g\,(v_{\text{cond}} - v_{\text{uncond}})\)。代价是每步两次前向。蒸馏过的模型把这个效果训进了一次前向里，就不需要了。H3 的 RL 配方里 guidance_scale 是 1.0，每步只跑一次。

Cosmos3 的配方 \(g = 4.0\)，而且它的「无条件」分支用的是负 prompt 而不是空 prompt。正、负 prompt 的 token 长度不同，模型一次又只接受一条序列，所以两次前向是先后跑的。

对 RL 来说，上面公式里的 \(v\) 是引导之后的速度。回放时两次前向都带梯度，所以被优化的是「带引导的策略」，和采样时一致。

一轮 FlowGRPO

把前面的东西串起来。Cosmos3-Nano 的配方是：16 步去噪，其中 2 步是 SDE 步，每个 prompt 生成 16 张图，PickScore 打分，只训练生成塔注意力上的 LoRA（秩 64）。

采样：16 步里挑 2 步

为什么只训 2 步：每个回放步都要带梯度跑模型，步数越少越省。为什么选中段，仓库里只写了沿用已有配方。我的理解是 \(\sigma\) 接近 1 时 \(\sigma/(1-\sigma)\) 很大，噪声过强；最后几步加的噪声来不及被去掉，图会脏。

一个 SDE 步的内部是这样的：

整个采样在 no_grad 下进行。只有抽中那两步前后的 latent 被存下来。

打分和组内比较

减组内均值是为了消掉「这句 prompt 本身好不好画」的影响。一张图只有一个优势值，它那条轨迹里被存下的两个 SDE 步共用这个值。

回放和损失

采样时没有梯度，所以要把存下来的 \((x, x_{\text{next}})\) 重新喂给模型，问一句：用现在的模型，从 \(x\) 走到这个 \(x_{\text{next}}\) 的概率是多少。

\[ \text{ratio} = \exp(\log p_{\text{new}} - \log p_{\text{old}}), \qquad L = \max\big(-A\cdot\text{ratio},\; -A\cdot\text{clip}(\text{ratio},\,1-c,\,1+c)\big) \]

\(A\) 是优势，\(c\) 是 clip_range。优势为正，就把均值 \(\mu\) 往当时实际走到的 \(x_{\text{next}}\) 挪一点；为负就往反方向挪。

每个样本的账是：采样 16 步 × 2 次前向 = 32 次；回放 2 步 × 2（正、负 prompt）× 2（旧、新）= 8 次。合计 40 次。一轮是 48 × 16 = 768 个样本。

裁剪在这份配方里其实没有生效

这是我读训练循环之后才确认的。一轮里的顺序是：先用当前权重回放得到旧 log-prob，然后逐个样本算损失、累积梯度，整轮只更新一次优化器（num_updates_per_batch: 1）。

算新 log-prob 的时候权重还没变，所以 ratio 恒等于 1，落不到裁剪区间之外。这时损失的梯度就是 \(-A\,\nabla \log p\)，带组内基线的普通策略梯度。代码里还有一个检查专门盯着这件事：第一次更新之前 ratio 如果偏离 1，就打印警告。

clip_range 只有在一批数据上更新多次时才真正约束步子。

同一个算法，两份配方

H3 的第一套配方用的也是 FlowGRPO，同一份算法代码，差别都在参数上：

Cosmos3-Nano MiniMax-H3
画布 832×480，单帧 256×384，124 帧加音频
去噪步数 16 10
加噪方式 FlowSDE CPS
CFG 4.0，每步两次前向 1.0，每步一次
每轮规模 48 个 prompt × 16 8 个 prompt × 16
奖励 PickScore ImageBind + CLAP
LoRA 秩 64，生成塔注意力 秩 32，注意力加前馈层
clip_range 1e-3 5e-3

H3 的奖励有一个坑，配方注释里记着：如果 ImageBind 只比较音频和视频，模型会学出黑屏加静音来刷分，所以必须带上文字到视频的那一项。

另一条路：DiffusionNFT

H3 还有第二套配方，用的是 DiffusionNFT。它不需要 log-prob，所以采样可以是纯确定性的（\(\eta = 0\)）。

做法是拿采样得到的干净 latent \(x_0\)，重新加噪到某个水平 \(t\)，让两个模型各预测一次速度：当前正在训练的 \(v_{\text{new}}\)，和一份滑动平均的旧权重给出的 \(v_{\text{old}}\)。然后构造一正一负两个预测：

\[ v^{+} = v_{\text{old}} + \beta\,(v_{\text{new}} - v_{\text{old}}), \qquad v^{-} = v_{\text{old}} - \beta\,(v_{\text{new}} - v_{\text{old}}) \]

正预测是从旧模型朝新模型走一小步，负预测是朝反方向走同样一步。每个预测都能还原出一张干净图 \(\hat{x}_0 = x_t - t\,v\)。

损失是

\[ L = r\,\lVert \hat{x}_0^{+} - x_0 \rVert^2 + (1-r)\,\lVert \hat{x}_0^{-} - x_0 \rVert^2 \]

其中 \(r \in [0, 1]\) 由优势换算而来：优势除以 5 截断到 \([-1, 1]\)，再线性映射到 \([0, 1]\)。代码里两项还各除以 \(\beta\)，并且可以按误差大小自适应加权，这里省略了。

好样本 \(r\) 接近 1，第一项起作用，把新模型拉向这张图。坏样本 \(r\) 接近 0，第二项起作用：让「反方向」的预测去拟合这张图，等价于把新模型推离它。

和 FlowGRPO 比，它不用存中间步，也不用为回放保留整条带梯度的计算图。H3 的 NFT 配方因此可以训练全部 10 个时间步。

要点回顾

  1. 扩散是生成方法，transformer 是网络结构，两者可以组合。Cosmos3 和 H3 都是扩散配 transformer。
  2. 判断几座塔，看同一层里不同模态是否用不同的主干权重。Cosmos3 是两座，H3 是一座。
  3. Cosmos3 的一层里注意力算两遍：文字只看文字；图像看文字加图像，其中文字的 K、V 是从理解塔借来的。
  4. 文字在推理、SFT、RL 回放三处都是整段给定的条件，被学习和被采样的只有图像那一段。
  5. 确定性采样没有概率。往某几步加高斯噪声，下一个 latent 就成了高斯策略的一次动作，log-prob 随之有了定义。
  6. FlowGRPO 一轮是：采样、打分、组内减均值得到优势、回放重算 log-prob、更新 LoRA。
  7. 每批只更新一次时 ratio 恒为 1，PPO 式的裁剪不起作用，训练等价于普通策略梯度。
  8. DiffusionNFT 不要 log-prob，改用「好样本拉近、坏样本推远」的加噪重训损失。

还没想明白的

  • 理解塔的 K、V 在 16 步里不变，缓存起来能省多少计算，我没有量过。
  • H3 的两份配方里，一处注释说 FlowGRPO 训练全部 10 步，另一处说它只负担得起 4 步，对不上，我没有去追是哪个过时了。
  • FlowSDE 的均值公式是怎么从 SDE 推出来的，这篇没有讲，我自己也还没有推过一遍。
